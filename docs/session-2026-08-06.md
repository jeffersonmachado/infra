## 5. Correção da VPN (rvpn) — Usuários Zerados

**Problema:** Após recriação da stack, o container `rvpn` estava online e healthy, mas com **0 usuários** configurados. O comando `UserList` retornava vazio.

**Causa raiz:** O `docker-compose.vpn.yml` montava o volume nomeado `vpn_softetherdata` em `/mnt`, mas o SoftEther lê a configuração de `/var/lib/softether/`. A imagem Docker declara `VOLUME /var/lib/softether`, fazendo o Docker criar um volume **anônimo** nesse path, que ficava com uma config vazia (sem usuários). A config real com os 3 usuários (`labrador`, `results`, `teste`) estava em `/mnt/vpn_server.config` e era ignorada.

**Correção aplicada:**

1. Alterado o mount no `docker-compose.vpn.yml`:
   ```yaml
   # Antes (errado):
   volumes:
     - softetherdata:/mnt
   
   # Depois (correto):
   volumes:
     - softetherdata:/var/lib/softether
   ```
2. Removidos os 3 volumes anônimos conflitantes (`/run/softether`, `/var/log/softether`, `/var/lib/softether`)
3. Container recriado com `docker compose -p vpn up -d --force-recreate`

**Atenção:** O project-name do Compose é `vpn` (declarado no `container_name`), não o nome do diretório. Comandos devem usar `-p vpn`:
```bash
docker compose -p vpn -f docker-compose.vpn.yml --env-file .env.vpn up -d
```

## 6. Correção das Senhas — Autenticação Inválida

**Problema:** Após restaurar os usuários do backup, o cliente não conseguia
autenticar. Todas as 4 contas ficavam em `Session Status: Repetindo` com
`Number of Established Sessions: 0`.

**Causa raiz:** O `vpn_server.config` contém hashes de senha (`AuthPassword`,
`AuthNtLmSecureHash`) que são criptografados com a chave interna do servidor
SoftEther. Quando o container é recriado (nova instância), essa chave muda e
os hashes antigos tornam-se inválidos — o servidor não consegue decriptar as
senhas originais.

**Correção:** Resetar as senhas diretamente no servidor via `vpncmd`, o que
gera novos hashes com a chave atual:

```bash
docker exec rvpn /usr/local/bin/vpncmd localhost:5555 /SERVER /HUB:DEFAULT \
  /PASSWORD: /CMD:UserPasswordSet results /PASSWORD:results@2026
docker exec rvpn /usr/local/bin/vpncmd localhost:5555 /SERVER /HUB:DEFAULT \
  /PASSWORD: /CMD:UserPasswordSet labrador /PASSWORD:labrador@2026
docker exec rvpn /usr/local/bin/vpncmd localhost:5555 /SERVER /HUB:DEFAULT \
  /PASSWORD: /CMD:UserPasswordSet teste /PASSWORD:teste@2026
```

Depois, atualizar as senhas no cliente:

```bash
sudo vpncmd localhost /CLIENT /PASSWORD:teste /CMD:AccountPasswordSet results /PASSWORD:results@2026 /TYPE:standard
sudo vpncmd localhost /CLIENT /PASSWORD:teste /CMD:AccountPasswordSet results-443 /PASSWORD:results@2026 /TYPE:standard
sudo vpncmd localhost /CLIENT /PASSWORD:teste /CMD:AccountPasswordSet labrador-443 /PASSWORD:labrador@2026 /TYPE:standard
```
