## 1. Galera Cluster (MySQL Multi-Master)

### Problema
Galera não estava deployado — sem imagem, sem containers, sem volumes.

### Solução
- **Imagem**: `mariadb-galera:10.11` (Dockerfile em `mysql-cluster/galera/`)
- **3 nós**: `srvmysql0` (10.10.2.79), `srvmysql1` (10.10.2.89), `srvmysql2` (10.10.2.49)
- **Rede**: `network_mode: host` com IPs no loopback para dev local

### Arquivos
| Arquivo | Descrição |
|---|---|
| `docker-compose.mysql-galera.yml` | Compose com 3 nós + healthcheck |
| `mysql-cluster/galera/Dockerfile` | Imagem base mariadb:10.11 + galera-4 |
| `mysql-cluster/galera/my.cnf.template` | Config renderizada via envsubst |
| `mysql-cluster/galera/entrypoint.sh` | Entrypoint com bootstrap/join |
| `scripts/deploy-galera.sh` | Script de deploy completo |
| `.env.mysql-galera` | Variáveis de ambiente |

### Correções aplicadas
- `wsrep_on = ON` explícito (sem isso o Galera não ativa)
- `wsrep_sst_receive_address` com porta única por nó (4444/4445/4446)
- `gmcast.listen_addr` e `ist.recv_addr` com IP específico (host network)
- Usuário SST (`galera`) criado automaticamente no bootstrap

### Deploy local
```bash
# Adicionar IPs ao loopback (uma vez por boot)
sudo ip addr add 10.10.2.79/24 dev lo
sudo ip addr add 10.10.2.89/24 dev lo
sudo ip addr add 10.10.2.49/24 dev lo

# Deploy
./scripts/deploy-galera.sh bootstrap
```

## 2. ProxySQL (Load Balancer SQL)

### Problema
Se um nó Galera cair, todas as aplicações perdem conexão (single point of failure).

### Solução
ProxySQL como balanceador na frente dos 3 nós Galera, usando o IP `10.10.2.99`.

### Arquivos
| Arquivo | Descrição |
|---|---|
| `docker-compose.proxysql.yml` | Compose standalone (host network) |
| `mysql-cluster/proxysql/proxysql-galera.cnf` | Config com 3 backends Galera |

### Arquitetura
```
Apps → srvmysql.results.intranet (DNS: 10.10.2.99) → ProxySQL → Galera (3 nós)
```

### Failover testado
- Parando `srvmysql0` → ProxySQL detecta (SHUNNED) → redireciona para `srvmysql2`
- Conexão continua ativa sem erro para a aplicação

## 3. DNS (PowerDNS)

### Problema
`pdns-auth` em crash loop — não alcançava MySQL em `10.10.2.99`.

### Solução
- Database `results` e schemas PowerDNS importados no Galera
- `pdns-auth` configurado para usar `srvmysql.results.intranet` (resolvido via `extra_hosts` no compose)
- `gmysql-host` alterado de IP hardcoded para hostname

### Arquivos alterados
| Arquivo | Mudança |
|---|---|
| `dns-consolidated/.env` | `DNS_DB_HOST=10.10.2.79` |
| `dns-consolidated/rendered/pdns-auth/pdns.conf` | `gmysql-host=srvmysql.results.intranet` |
| `dns-consolidated/mariadb/init/02-zone-data.sql` | `srvmysql.results.intranet` → `10.10.2.79` |

### DNS atual
```
srvmysql.results.intranet → 10.10.2.99 (ProxySQL)
```

## 4. Container Health Fixes

### Mail (dovecot, ldap, rspamd)

- **Solução**: Recriados com healthcheck do compose (usa `/dev/tcp` do bash)

## 5. Logs — Promtail → Loki

### Problema
Apenas serviços com OTel SDK enviavam logs para Loki. Logs de stdout do Docker (json-file) não chegavam ao Loki.

### Solução
Adicionado `r-observe-promtail` que coleta logs de **todos os containers** via Docker socket e envia para Loki.

### Arquivos
| Arquivo | Descrição |
|---|---|
| `docker-compose.observe.yml` | Serviço `r-observe-promtail` adicionado |
| `observe/promtail/promtail-config.yml` | Config com `docker_sd_configs` |
| `observe/loki/loki-config.yml` | `reject_old_samples: false`, limits aumentados |

## 6. Icinga2 — Auto-Attach de Redes

### Problema
Icinga2 não alcançava containers em outras redes Docker (checks com 100% packet loss).

### Solução
- Script `auto-attach-networks.sh` no entrypoint do Icinga2
- Conecta automaticamente a TODAS as redes Docker ao iniciar
- Docker socket montado no container

### Arquivos
| Arquivo | Descrição |
|---|---|
| `observe/icinga2/Dockerfile` | Adicionado `curl`, grupo `docker` (GID 137) |
| `observe/icinga2/auto-attach-networks.sh` | Script de auto-attach |
| `observe/icinga2/observe-init.sh` | Chama auto-attach antes do daemon |
| `docker-compose.observe.yml` | Monta `/var/run/docker.sock` no Icinga2 |

## 7. Discovery — Auto-Scan Generalista

### Problema
Discovery com 0 targets de scan ativo. Hosts estáticos hardcoded no compose.

### Solução
- `autoDiscoverEnabled = !isDocker` → `autoDiscoverEnabled = true` (sempre tenta auto-detectar)
- `OBSERVE_STATIC_HOSTS` default trocado de `[{mariadb,...}]` para `[]`
- Targets agora derivados automaticamente de:
  - Subnets Docker (`docker network inspect`)
  - Rotas do host (`/proc/net/route`)
  - IPs vizinhos (ARP)

### Arquivos alterados
| Arquivo | Mudança |
|---|---|
| `r-observe/discovery/src/engine/discovery-engine.js` | `autoDiscoverEnabled = true` |
| `docker-compose.observe.yml` | `OBSERVE_STATIC_HOSTS: []` |

## 8. AI / DeepSeek

### Problema
IA chamando DeepSeek mas retornando análise vazia (campos NULL no banco).

### Causas (3 problemas):
1. **Modelo errado**: `deepseek-v4-pro` é modelo reasoning — todo output ia para `reasoning_content`, não `content`
2. **Sem `response_format`**: DeepSeek não era forçado a responder em JSON
3. **Prompt inferia causalidade**: IA correlacionava incidentes sem evidência direta

### Soluções
| Arquivo | Mudança |
|---|---|
| `r-observe/ai/src/index.js` | `callDeepSeek` com `response_format: json_object`, fallback sem, leitura de `reasoning_content` |
| `observe_ai_settings` (DB) | Modelo: `deepseek-v4-pro` → `deepseek-chat` |
| `r-observe/ai/src/index.js` | SYSTEM_PROMPT: "NUNCA infira causalidade de outros incidentes" |
| `r-observe/ai/src/index.js` | REMEDIATION_CATALOG: 4 ações → 13 ações generalistas |
| `r-observe/ai/src/index.js` | Prompt: catálogo como "referência", não "limite" |

## Scripts de Deploy

| Script | Função |
|---|---|
| `scripts/deploy-galera.sh [bootstrap]` | Deploy do cluster Galera |
| `docker-compose.proxysql.yml` | ProxySQL (comando direto) |
| `/opt/results/r-observe/docker-compose.observe.yml` | Stack r-observe (profiles) |
| `docker-compose.mail.yml` | Stack de email |

### Deploy completo (dev local)
```bash
# 1. Adicionar IPs
sudo ip addr add 10.10.2.79/24 dev lo
sudo ip addr add 10.10.2.89/24 dev lo
sudo ip addr add 10.10.2.49/24 dev lo
sudo ip addr add 10.10.2.99/24 dev lo

# 2. Galera
./scripts/deploy-galera.sh bootstrap

# 3. ProxySQL
docker compose -f docker-compose.proxysql.yml up -d

# 4. DNS
cd dns-consolidated && docker compose up -d

# 5. r-observe (todos os profiles)
cd /opt/results/r-observe
docker compose -f docker-compose.observe.yml --env-file .env.observe \
  --profile observe-core --profile observe-ai --profile observe-agent \
  --profile observe-icinga --profile observe-monitoring --profile r-observe-proxy \
  up -d

# 6. Mail
cd /opt/results/infra
docker compose -f docker-compose.mail.yml --env-file .env.remote-10.10.2.30-mail up -d
```
