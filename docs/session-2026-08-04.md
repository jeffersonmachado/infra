## Problemas encontrados e correções

### 1. ProxySQL fora do ar (10.10.2.99)

**Causa:** após ressincronização dos nodes Galera, usuário `proxysql` foi perdido e senha do `resultsdba` ficou inválida.

**Correção:**
```sql
CREATE USER IF NOT EXISTS 'proxysql'@'192.168.48.%' IDENTIFIED BY 'pr0xysqlm0n';
CREATE USER IF NOT EXISTS 'proxysql'@'10.10.2.%' IDENTIFIED BY 'pr0xysqlm0n';
GRANT USAGE ON *.* TO 'proxysql'@'192.168.48.%';
GRANT USAGE ON *.* TO 'proxysql'@'10.10.2.%';

-- Resetar senha do resultsdba
SET PASSWORD FOR 'resultsdba'@'192.168.48.%' = PASSWORD('resu100dba');
SET PASSWORD FOR 'resultsdba'@'%' = PASSWORD('resu100dba');
SET PASSWORD FOR 'resultsdba'@'10.10.2.30' = PASSWORD('resu100dba');
FLUSH PRIVILEGES;
```

**Arquivos copiados para o servidor (não existiam em produção):**
- `docker-compose.proxysql.yml`
- `mysql-cluster/proxysql/proxysql-galera.cnf`

### 2. Roundcube — botão "Não é lixo" na INBOX

**Problema:** o plugin `markasjunk` do Roundcube mostra o botão "Não é lixo" apenas na pasta Spam. O usuário precisava de acesso a ele em qualquer pasta.

**Correção (container `results-joomla`):**
- `plugins/markasjunk/markasjunk.js` — função `toggle_button` modificada: ambos botões (Spam e Não é lixo) sempre visíveis
- `plugins/markasjunk/markasjunk_override.js` — handler extra via evento `markasjunk-update` para garantir visibilidade
- `plugins/markasjunk/markasjunk.php` — incluído `$this->include_script("markasjunk_override.js")`

### 3. Dovecot — aprendizado por flag IMAP

**Problema:** o aprendizado de HAM/SPAM só ocorria ao mover emails entre pastas (COPY Spam↔INBOX). O botão "Não é lixo" na INBOX seta flag `NonJunk` sem mover o email.

**Correção (container `results-mail-dovecot`):**
- Novos scripts sieve:
  - `sieve/learn-ham-flag.sieve` — aprende HAM quando flag `NonJunk` é setada
  - `sieve/learn-spam-flag.sieve` — aprende SPAM quando flag `Junk` é setada
- Novas regras imapsieve no `local.conf`:
  ```
  imapsieve_mailbox5_name = *
  imapsieve_mailbox5_causes = FLAG
  imapsieve_mailbox5_before = file:/etc/dovecot/sieve/learn-ham-flag.sieve

  imapsieve_mailbox6_name = *
  imapsieve_mailbox6_causes = FLAG
  imapsieve_mailbox6_before = file:/etc/dovecot/sieve/learn-spam-flag.sieve
  ```
- Template `dovecot.conf.template` atualizado com as regras acima

### 4. Treino automático de HAM (cron)

**Script:** `scripts/train-rspamd-ham.sh`

- Executa no host via cron: `*/10 * * * *`
- Só processa se `BAYES_HAM < 200` (classificador Bayes precisa de 200 amostras)
- Usa `doveadm user '*'` ou variável `ACTIVE_USERS=jefferson,wedila` para filtrar usuários ativos
- Busca emails com +60 dias nas pastas `cur/` (exclui Spam, Junk, Trash, etc.)
- Envia para `rspamc learn_ham` via container rspamd
- Seta flag IMAP `NonJunk` em cada email treinado (igual ao botão "Não é lixo")
- Batch size: 50 emails por execução
- Log de auditoria: `/var/log/train-rspamd-ham-files.log`
- Log de execução: `/var/log/train-rspamd-ham.log`

**Cron:**
```
*/10 * * * * ACTIVE_USERS=jefferson,wedila /opt/results/infra/scripts/train-rspamd-ham.sh >> /var/log/train-rspamd-ham.log 2>&1
```

### 5. Bayes rspamd — reset e configuração

- Backend: Redis (`BAYES_HAM_keys`, `BAYES_SPAM_keys`)
- Modelo global (`users: 1`), não por usuário
- `min_learns = 200` — classificador só ativa após 200 amostras
- Para resetar: parar rspamd, deletar chaves Redis, reiniciar

### 6. IPs fixos na rede infra-shared

**Problema:** `extra_hosts` no docker-compose.yml precisava de IPs estáveis. Containers de email recebiam IPs dinâmicos do Docker, quebrando a resolução após restarts.

**Correção:** IPs fixos via `ipv4_address` no `docker-compose.mail.yml`:

| Container | IP |
|---|---|
| `results-mail-dovecot` | `192.168.48.14` |
| `results-mail-postfix` | `192.168.48.11` |
| `results-mail-postfix-mx2` | `192.168.48.12` |

E `extra_hosts` no `docker-compose.yml` (serviço `joomla`):
```yaml
extra_hosts:
  - "srvmysql.results.intranet:10.10.2.79"
  - "results-mail-dovecot:192.168.48.14"
  - "results-mail-postfix:192.168.48.11"
```

### 7. Migração Apache: mpm_prefork → mpm_event

**Problema:** Apache mpm_prefork (single-thread) com 10-20 workers causava fila de
requisições AJAX concorrentes do Roundcube, resultando em "Falha na comunicação
com o servidor".

**Solução:** rebuild da imagem Docker com `php:7.4-fpm` + Apache via apt +
mpm_event + proxy_fcgi.

| Componente | Antes | Depois |
|---|---|---|
| Imagem base | `php:7.2-apache` | `php:7.4-fpm` + Apache |
| PHP | 7.2.34 (Debian Buster, EOL) | 7.4.33 (Debian Bullseye) |
| MPM | prefork (processos) | event (threads) |
| PHP handler | mod_php | php-fpm via proxy_fcgi |
| Workers | 10-20 processos | 50 threads (php-fpm pool) |

**Arquivos alterados:**
- `joomla/Dockerfile` — nova imagem base, Apache via apt, mpm_event, php-fpm
- `joomla/docker-entrypoint.sh` — inicia php-fpm antes do Apache

**Nota:** após rebuild, as customizações do markasjunk precisam ser reaplicadas
no container (não persistem no volume).

## Como usar (usuário final)

| Ação | Onde | Botão | Efeito |
|---|---|---|---|
| Marcar SPAM | Qualquer pasta | **Spam** | Move p/ Spam, flag `Junk`, `rspamc learn_spam` |
| Marcar HAM | Qualquer pasta | **Não é lixo** | Flag `NonJunk`, `rspamc learn_ham` |
| Ver HAM marcados | Busca Roundcube | `KEYWORD NonJunk` | Lista emails com flag |
| Desmarcar HAM | Selecionar email | **Spam** | Remove `NonJunk`, adiciona `Junk` |
